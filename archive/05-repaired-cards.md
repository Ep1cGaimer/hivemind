## R11 — shared institutional capability memory

Same user: operations lead or account-planning lead asking a qualified company-capability question. Same problem: repeated role-agent memories appear to corroborate a broader claim than their common source supports. The discarded launch-approval example was defeated by a mandatory owner-source check; it is not our evidence now.

One memory gateway over FalkorDB stores company entities, source excerpts, immutable role-agent memories, observed read/write runs, proposed claim-level source support and reviewed qualifications. READ/IN_CONTEXT records exposure only. CLAIMS_SUPPORT is a model proposal with exact span and qualified proposition. REVIEWED_SUPPORT records an actual reviewer acceptance for that proposition/scope; never implies independent truth or blanket approval. Do not infer causation of model output from context access. Source roots/paths identify documented support, not source independence or a consensus score. Shared background can coexist with distinct separately recorded observations.

Agent A learns/proposes a source-backed qualified memory. Agent B, genuinely cold, retrieves evidence/derivation paths, compares raw support with the current entity/scope, and asks a targeted missing-evidence question or drafts a bounded next step. An explicitly reviewed clarification is persisted; a later cold role can use it within its exact scope. No automatic business authorization from roots, claim status or review count. One loop with two role sessions; broad swarm/connectors are excluded P0.

30s candidate story: multiple role memories say a capability is ready; trace their claimed support to the same conditional observation. Agent asks the condition-specific question, rather than treating repetitions as new evidence. Review clarifies applicability to this case; a restarted role uses the corrected qualified memory. No fabricated baseline miss or actual runtime outcome claimed. The graph must select source/consumer paths inside the loop, not decorate a precomputed result.

Keep <=8 source/memory items per case, one capability, two relevant company scopes, two cold sessions and one reviewer action. Optional controlled third memory only if needed to show a derivation chain. No security declassification, numeric trust model, enterprise ingestion stack or unbounded ontology.

Strongest counter: V6 already studies correlated sources; Graphiti/Glean/MAP-style memory may supply the same context; direct source+origin-ID+same-agent controls may ask equally good questions. Human support review and lineage could cost more than reuse saves. Required falsifier: do not collapse distinct observations via background READ links; do not promote unknown support; do not apply a reviewed qualifier to unrelated scope. Paper inputs/oracle are being authored separately to test this, not to declare a winner.

## R03 — observed-coverage handover memory

Same manager/successor problem, repaired to start from a concrete successor task and observed artifact/dependency paths. No sole-knower or undocumented-thought inference. The agent reads available raw sources, identifies a relevant unresolved question under explicitly incomplete source coverage, obtains a simulated/reviewed answer and persists it. Cold successor must change a concrete draft using that newly learned scope/rationale. No SHOULD_ASK or missing-rationale verdict field, no inferred successor authority.

Four-day minimum: one task, three decisions/artifacts, one indirect dependent, one alternative rationale source, one interview/review loop, a later cold session. Capable control gets identical notes and question budget. Fail if generic targeted handover plus same agent finds equal useful questions with less prep.

NEW V13 is a direct objection, not merely a missing market check: Flamekeeper, Implix and Culturro advertise role-specific knowledge/gap discovery, interviews and reviewed successor handover. Their pages do not prove implementation parity, but they remove generic 'find gaps -> interview -> approved handover' as differentiation. Defend a precise observed dependency and cross-agent reuse job or reject; no automatic graph-based novelty. Adding more features or rebranding is not a repair.

## R06 — raw scoped-acceptance handoff memory
