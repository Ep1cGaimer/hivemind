# Paper review and limits

The four packets in 05-blind-memory-inputs.md and the separate 05-author-oracle.md were authored by Sol. All logs and observations are synthetic input descriptions, not executed agent runs.

Astra completed a blind interpretation before the oracle was opened by the chair. Its exact response is saved in 06-astra-blind.md. The chair subsequently read the oracle after the other blind attempts had terminated with transport errors; no later answer is counted as blind. Sol is the author, not an independent blind judge.

| Packet | What the completed interpretation preserves | Limit of the exercise |
|---|---|---|
| M-47 | Separate header and attachment observations despite shared naming background; a combined walkthrough is proposed, not proven. | Distinct recorded runs do not establish statistical independence or successful combined behavior. |
| M-12 | Reserved-pool limitation; derivative summaries and terminology do not add trials; ask which pool applies. | A complete-source control can ask the same question. |
| M-83 | Reviewed Maple-evaluation correction; ask workspace scope; Cedar receives neither the correction nor new validation. | The review is authored as authentic; no permission/review service was tested. |
| M-26 | Offline report has unknown support and unknown cache/revision; READ cannot reconstruct semantic dependence. | No actual offline test, runtime capability conclusion, or provenance advantage follows. |

The author oracle permits multiple properly bounded answers. Astra's reasoning is consistent with its central distinctions. This is a logical consistency review, not a four-out-of-four accuracy result or proof of durable memory.

Opus and Sonnet blind calls returned API timeout errors. Muse's blind attempt returned ECONNRESET. Their missing answers are not failures on the packets and cannot count as agreement, safety evidence, or a measured model result.

The useful design lesson is that qualification, scope and uncertainty must survive recall. These tiny explicit packets also sharpen the strongest counterargument: reading the complete source can supply every correct answer. The real rejection test must compare useful cold-session work and preparation effort after an actual write-and-read loop.
