# Anonymized normalized cards — independent scoring inputs

Thirteen cards from independent generation. No model attribution, scores or preferred candidate supplied. All are additional Track 2+3 concepts; RollbackWitness stays main. Complete original cards preserved separately. Defaults for every card: synthetic/permitted data only; exact provenance/permissions; deterministic scoped query/action control, LLM grounded interpretation; human-approved local draft/transfer only; no actual message, contract, employee decision, or production change. No deployed/benchmark result exists.

Same model, raw sources/serialized edges, updates, tools and comparable budget go to isolated/flat/vector and complete SQL/BFS-with-same-LLM controls. SQL correctness parity is allowed. No baseline is required to fail, no invented numerical improvement. One reliable memory loop, two cold-start role sessions; agent count alone has no value. Demand/preparation/competitive gaps are hypotheses unless supported by 02-validation-evidence.

## H01 — Origin-aware product evidence
User/problem: product-operations lead deciding a roadmap brief; repeated research/sales/support summaries can make one conditional customer observation look like many supporting requests. Current method: feedback repository/CRM, search and manual counting.
Graph: Feature <- ABOUT- qualified Claim -> DERIVED_FROM* -> observed source Interaction -> Account; Artifact/AgentRun/Review and SUPPORTS paths. Collapse recorded common origins, expose unknown roots/cycles, keep different outcomes/qualifiers apart. Removing tools loses connected origin grouping/witnesses, not records.
Agent: interpret raw requests and qualifiers, propose source-backed grouping, investigate missing origins, draft revised brief for lead approval. Data:12 artifacts/3 accounts/2 features; two role sessions. Demo: five reports become one qualified origin plus a different request/unknown, later session retains reviewed distinctions.
Substitutes/differentiation: Productboard/Dovetail already source-link and de-duplicate customer feedback; V6 already studies correlated sources. Gap hypothesis only: cross-agent multi-hop lineage rather than ordinary account counting. Four-day minimum: fixtures/oracle, ancestry tools, intake-to-product handoff, controls. Biggest rejection: lineage prep plus a customer-ID table solves it. Falsifier: blinded copies/independent/ambiguous sources must preserve real separate observations and unknowns without answer tags; report parity honestly.

## H02 — Permission-preserving derived company memory
User/problem: internal AI-platform owner enabling employees' agents to share derived company memory without leaking restricted source content. Current method: isolated memory or document ACLs; hypothesized lineage loss in derived text.
Graph: User -> Group -> allowed Source; Memory -> DERIVED_FROM* -> Source; Session/Claim/SupportSet variants. Traverse full observed ancestry under current ACLs. Variant A gates all observed contributing sources and regenerates from permitted-only context; variant B alternative reviewed support sets. Do not automatically declassify a derived secret because another public source mentions a similar claim. Removing tools loses read-time derivation/visibility witness and change impact.
Agent: choose permissible re-derivation/partial answer/abstention, source-ground support proposals for review. Deterministic gate before context; no secret/existence/count leak. Data:12 sources/3roles/2sessions. Demo: employee gets public merger context without restricted detail; source revocation removes dependent reusable memory.
Substitutes: V1/V3–V5 are very close; this is not new research. Four-day minimum: bounded derivation tree, read gate, isolated regeneration, revocation check. Risk: security scope or ACL intersection suffices. Test actual conservative ACL/recompute and lineage-aware controls; reject superficial differentiation or a leakage-prone support shortcut.

## H03 — Coverage-driven knowledge handover
User/problem: engineering/operations manager preparing a departure/role change; documents don't reveal which active decisions/artifacts lack a second observed source/attestor. Current: handover doc, generic exit interview, bus-factor/ownership analytics.
Graph: departing Person -> authored/reviewed/attested Decision/Artifact -> active dependents, with explicit alternative current attestation paths, source coverage and transfer records. Find modeled concentration/gaps, rank impact and ask targeted interview questions. Variants: sole-attestor authority (approval required), single-owner+missing documentation, artifact risk with co-review successors. No missing edge proves actual sole knowledge; co-work is a suggestion, not expertise/authority.
Agent: interpret raw decision evidence, ask targeted questions, propose source-grounded handover packet; manager approves, cold-start successor reads it with citations. Data:small synthetic team,5decisions/3systems before larger optional fixture. Demo: potential concentrated rationale -> targeted answer -> later agent can answer with approved source, preserving unknowns.
Removal loses alternative-path coverage/impact/transfer receipts. Substitutes: bus-factor scripts, service catalogs, wikis and knowledge tools. Four days: fixture, coverage tools, interview/review, successor controls. Biggest risk: pretending unrecorded knowledge can be inferred. Falsifier: known alternative evidence/partial coverage decoys must not be labeled sole-knower; compare generic interview/script+same agent.

## H04 — Live expertise rerouting

Graph: system <- contributed/reviewed/owns- active Person -> Team/Role, evidence and explicit authority; optional successor paths. Retain no distinction between contribution and permission: authority must be an explicit separate record. Agent reads evidence, proposes a qualified reviewer/asks approval owner; human approves any reassignment.
Data:synthetic small org/tickets; demo stale author -> current candidate with evidence, no automatic authorization. Removing paths loses live successor evidence. Risk: ordinary active filter plus owner field solves it. Falsifier: withheld active/authority and misleading co-team decoys; no unsupported 'can approve' claims. Baseline outcomes unmeasured.
